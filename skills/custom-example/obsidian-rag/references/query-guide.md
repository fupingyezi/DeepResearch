# obsidian-rag 查询指南

## 索引（rag-index.sh）

- 增量建库：按 `mtime + sha256` 跳过未变文件，只处理新增/修改过的 markdown
- 隐藏文件与隐藏目录被跳过
- 笔记按标题层级切块，`headingPath`（如 `Redis > 持久化 > AOF`）会拼进向量化文本——短术语问题（「AOF 是什么」）靠它命中正文里没写这个词的片段
- 判断索引新旧：`rag-stats.sh` 看文件数/片段数；刚改过笔记就先 `rag-index.sh`

## 提问（rag-ask.sh）

```
rag-ask.sh <问题> [-k 片段数] [-t 标签1,标签2]
```

- `-k`：交给生成模型的片段数，默认 5；问题涉及面广时可加到 8~10
- `-t`：按标签过滤，要求片段包含全部给定标签（用户说「关于数据库的笔记」→ `-t 数据库`）
- 检索两路召回：向量 KNN（语义）+ FTS5 关键词（精确术语，中文 segmentit 预分词）→ RRF 融合 → rerank 精排 → 前 k 条交给 LLM
- 答案逐条给出来源，格式为 `文件:行号`；原样转达给用户

## 回答边界（重要）

- 管线系统提示要求**只根据给定片段回答**，片段不够就明说「笔记中没有相关记录」——不编造
- 若回答显示「笔记中没有」，如实转达；不要用自己的常识补答案并暗示来自笔记
- 笔记库只覆盖用户写过的东西：问「笔记里有没有 X」但实际想查外部知识时，应改用 `deep-research` skill 做网络调研

## 常见失败排查

- **run 返回脚本内容而非执行结果**：host bash 未开（`DEERFLOW_ALLOW_HOST_BASH`），或沙箱不可用——告知用户并给出脚本内容
- **60s 超时**：`ask` 里含 LLM 生成，超时后底层进程可能仍在跑但结果拿不到——建议应用侧把 `DEERFLOW_SKILL_SCRIPT_TIMEOUT_MS` 提到 120000+，或重问一次
- **`npm run index` 慢**：首次全量建库最慢（全库向量化），之后增量很快；报「卡住」时先看是不是 API 429 自动退避（openai SDK 指数重试的表现）
- **serve 起不来**：看 `/tmp/obsidian-rag-mcp.log`；端口被占（`lsof -ti :3333`）先 `rag-kill.sh`
